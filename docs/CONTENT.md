# Προσθήκη μαθημάτων και περιεχομένου

Η εφαρμογή δεν περιέχει ειδική λογική Δικτύων ή Προγραμματισμού στην πλοήγηση. Το `data/course-registry.json` δηλώνει τα μαθήματα/ειδικότητες, τα `data/courses/*.json` τις επιμελημένες τράπεζες, και το `scripts/build_data.py` ελέγχει τα δεδομένα και παράγει το offline JavaScript. Οι ερωτήσεις κάθε μαθήματος φορτώνονται όταν επιλεγεί.

## Νέο μάθημα

1. Πρόσθεσε την ειδικότητα στο λεξικό `specialties` του registry, εφόσον δεν υπάρχει.
2. Πρόσθεσε καταχώριση στο `courses`, με νέο σταθερό `id`, `title`, `specialtyIds`, `specialtyLabel`, `grade`, `input`, `script`, `book`, `syllabusSource`, `extensions`.
3. Δημιούργησε το JSON της τράπεζας με `version: 2`, `subjectId`, `chapters`, `sections`, `syllabus`, `collections`, `questions`, `sourceNote`.
4. Τρέξε `npm run build:data`, `npm test` και `npm run package`.

Παράδειγμα καταχώρισης (τα αρχεία πρέπει να υπάρχουν):

```json
{
  "id": "mathematics",
  "title": "Μαθηματικά",
  "specialtyIds": ["general"],
  "specialtyLabel": "Γενικής παιδείας",
  "grade": "Γ΄ ΕΠΑΛ",
  "input": "data/courses/mathematics.json",
  "script": "data/courses/mathematics.js",
  "book": "assets/mathematics/book.pdf",
  "syllabusSource": "data/courses/mathematics-syllabus.md",
  "extensions": []
}
```

Τα κεφάλαια έχουν string IDs: `"11"`, όχι υποχρεωτικά μονοψήφια. Μια παράγραφος έχει τιμή `["Τίτλος", τυπωμένη_σελίδα]`. Οι τρέχουσες εκδόσεις βιβλίων έχουν την τυπωμένη σελίδα μία θέση πριν από τη σελίδα του PDF. Για άλλη έκδοση, όρισε `pdfPage` σε κάθε `bookRefs` ώστε να μην εφαρμοστεί το προεπιλεγμένο `page + 1`.

## Πρόβλεψη για πιθανές μελλοντικές πηγές

Αυτές οι πηγές δεν είναι ενεργές στο τρέχον UI. Η εφαρμογή περιορίζει ρητά την εξάσκηση σε `sourceKind: "exam"`. Το παρακάτω σχήμα διατηρείται για πιθανή μελλοντική ενεργοποίηση· η προσθήκη αρχείου μόνη της δεν εμφανίζει τις ασκήσεις. Δεν χρειάζεται νέο μάθημα. Δημιούργησε π.χ. `data/collections/programming-teacher.json` και πρόσθεσε τη διαδρομή στο `extensions` του μαθήματος. Το αρχείο περιέχει:

```json
{
  "subjectId": "programming",
  "collections": {
    "programming-teacher-01": {
      "title": "Επανάληψη καθηγητή — συναρτήσεις",
      "kind": "custom"
    }
  },
  "questions": []
}
```

Οι διαθέσιμες προελεύσεις είναι `exam`, `workbook`, `custom`. Κάθε συλλογή έχει δικό της ID, τίτλο και προέλευση. Τα `tags` μπορούν μελλοντικά να χρησιμοποιηθούν ως φίλτρα (π.χ. `επανάληψη`, `βασικό`, `εργαστήριο`). Οι συλλογές μπορούν να συνυπάρχουν στο ίδιο μάθημα χωρίς να μπερδεύονται με τις εξετάσεις.

Οι δικές μας ερωτήσεις μπορούν να έχουν `year: null`. Το «Ανά έτος» φιλτράρει αποκλειστικά συλλογές `exam`, και επιλέγεται συγκεκριμένη εξέταση· έτσι υποστηρίζονται μελλοντικά και διαφορετικές εξεταστικές περίοδοι του ίδιου έτους. Δεν πρέπει να χρησιμοποιείται πλασματικό έτος για άσκηση τετραδίου.

## Κοινά πεδία ερώτησης

```json
{
  "id": "programming:custom:teacher-01:001",
  "subjectId": "programming",
  "sourceKind": "custom",
  "collectionId": "programming-teacher-01",
  "year": null,
  "key": "1",
  "order": 1,
  "sections": ["4.2.1"],
  "chapters": ["4"],
  "inSyllabus": true,
  "classificationStatus": "curated",
  "tags": ["επανάληψη"],
  "type": "reading",
  "prompt": "Η εκφώνηση που συνέταξε ο εκπαιδευτικός.",
  "original": "Η αρχική εκφώνηση.",
  "explanation": "Η επιμελημένη ενδεικτική απάντηση.",
  "answerStatus": "provided",
  "answerSources": [{"author": "Ονοματεπώνυμο εκπαιδευτικού"}]
}
```

Αυτό είναι υπόδειγμα δομής, όχι ερώτηση που προστίθεται αυτόματα στην τράπεζα.

Για αρχείο πηγής πρόσθεσε `source` και `pages` (σελίδες PDF, από 1). Για εικόνες πρόσθεσε `images`. Οι παραπομπές λύσεων έχουν `sourceId`, `path`, `pages`, `label`. Οι δικές μας λύσεις μπορούν να έχουν `author` αντί για PDF. Η παραπομπή εμφανίζεται μετά τη διόρθωση/αποκάλυψη και στις πηγές της ερώτησης.

Το `inSyllabus` είναι αποτέλεσμα επιμέλειας με βάση το αρχείο ύλης, όχι δυναμική εκτίμηση λέξεων-κλειδιών. Σε μικτά θέματα γίνεται `true` μόνο εφόσον καλύπτονται όλες οι σχετικές παράγραφοι. Η αντιστοίχιση και το φίλτρο παραγράφων είναι ακριβή, χωρίς αυτόματη ένταξη όλων των υποπαραγράφων.

## Τύποι απαντήσεων

| `type` | Επιπλέον δεδομένα |
|---|---|
| `boolean` | `correct: true` ή `false` |
| `choice` | `options: [{id, label}]`, `correct` ίσο με ID επιλογής |
| `match` | `items: [{id, label, correct, accepted?}]`, `options` |
| `fields` | `fields: [{label, kind, answers}]` |
| `order` | `items: [{id, label}]`, `correct: [id, ...]` |
| `reading` | Μόνο εκφώνηση και λύση, χωρίς υποχρεωτικό input |

Πεδία `kind`: `number` (ακέραια μεγέθη, δέχεται διαχωριστικά χιλιάδων), `decimal` (πραγματικοί με τελεία/κόμμα, χωρίς διαχωριστικά χιλιάδων), `binary`, `ip`, `mask`, `mac`, `hex`, `text`, `literal`, `code`, `sequence`, `set`, `expression`.

- Για δεκαδικούς μαθηματικών χρησιμοποίησε `decimal`: η τιμή `1.232` δεν μετατρέπεται σε `1232`.
- Το `text` αγνοεί κεφαλαία/πεζά και τόνους. Το `literal` διατηρεί κεφαλαία, τόνους και εσωτερικά κενά.
- Το `code` διατηρεί κεφαλαία/πεζά, περιεχόμενο συμβολοσειρών και όρια λεκτικών μονάδων. Επιτρέπει διαφορετικά εξωτερικά κενά και ισοδύναμα εισαγωγικά. Δεν εκτελεί τον κώδικα και δεν αποδεικνύει αλγοριθμική ισοδυναμία· πρόσθεσε στο `answers` τις αποδεκτές εναλλακτικές.
- Το `sequence` συγκρίνει διατεταγμένες αριθμητικές ακολουθίες, δεχόμενο κενά, κόμματα ή αγκύλες. Δεν αγνοεί τη σειρά ή επαναλαμβανόμενες τιμές.
- Για πλήρη προγράμματα ή αποδείξεις, χρησιμοποίησε `reading`. Δεν απαιτείται απάντηση από τον μαθητή.

Τα `preserveLayout` / `solutionLayout` διατηρούν πίνακες ή εσοχές σε περιοχή με οριζόντια κύλιση. Το `answerExcerpt` διατηρείται στα δεδομένα για εσωτερική αντιπαραβολή και δεν εμφανίζεται στην εφαρμογή. Το `supplement` προσθέτει συμπληρωματική εξήγηση. Σε διαφωνίες πηγών, πρόσθεσε `reviewOnly: true`, `answerStatus: "conflict"`, σχετικό `note` και τις αντικρουόμενες παραπομπές.

## Εισαγωγή PDF και συντήρηση

Τα επιμελημένα `data/courses/*.json` είναι η κύρια πηγή δεδομένων. Το κανονικό build δεν χρειάζεται τα αρχικά PDF έξω από την εφαρμογή ή πρόγραμμα εξαγωγής κειμένου. Το `data/imports/` διατηρεί κείμενα/κατάλογο πηγών για εσωτερική αντιπαραβολή και δεν δημοσιεύεται.

Το `scripts/import_content.py` είναι βοηθητικό εισαγωγής των συγκεκριμένων τοπικών αρχείων, όχι γενικός αυτόματος λύτης. Γράφει ενδιάμεσο `data/programming-import.json`, χωρίς να αντικαθιστά την επιμελημένη τράπεζα. Νέες εκφωνήσεις, ταξινόμηση και απαντήσεις πρέπει να ελέγχονται πριν προστεθούν στο JSON. Τα θέματα Pascal εξαιρούνται ρητά από την εισαγωγή.

Ο builder απορρίπτει διπλά IDs, άγνωστα μαθήματα/συλλογές/παραγράφους, ελλιπείς απαντήσεις και χαμένες πηγές. Οι νέες συλλογές ενσωματώνονται πριν δημιουργηθεί το offline script. Το ZIP περιλαμβάνει μόνο όσα αρχεία χρησιμοποιούν οι ενεργές τράπεζες.

## Μορφοποίηση εκφωνήσεων

Το προαιρετικό `promptBlocks` υπερισχύει της παλιάς εμφάνισης `preserveLayout`. Υποστηρίζει `paragraph` / `note` με `text`, `code` για κώδικα με εσοχές, `pre` για διατάξεις που χρειάζονται ακριβή στοίχιση, `table` με `headers` και `rows`, και `list` με `items: [{label, blocks}]`. Οι λίστες κρατούν τις αρχικές ετικέτες (α., β., Γ1. κ.λπ.). Τα δεδομένα είναι απλό κείμενο που γίνεται escaped πριν αποδοθεί ως HTML· δεν εισάγουμε αυθαίρετο HTML στα JSON.

Οι παράγραφοι αναδιπλώνονται ανάλογα με την οθόνη. Μόνο ο κώδικας και οι πίνακες μπορούν να έχουν εσωτερική οριζόντια κύλιση. Το `original` και τα PDF διατηρούνται αυτούσια για αντιπαραβολή. Το `scripts/migrations/format_prompts.py` καταγράφει την αρχική μετατροπή των συγκεκριμένων τραπεζών· δεν αποτελεί μέρος του κανονικού build και δεν πρέπει να ξανατρέξει πάνω σε μεταγενέστερη επιμέλεια χωρίς έλεγχο.
